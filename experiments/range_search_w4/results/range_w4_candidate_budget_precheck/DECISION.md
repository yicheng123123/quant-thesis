# candidate_budget_precheck 决策

## 结论

**值得冻结一个较小的、逐 Linear 候选集供后续独立验证；本次不启动验证。** 完整 v18 M2 历史表覆盖 168 个 Linear、304,128 个输出行。逐模块保留 alpha=1 与该 Linear 在原 M2 search 中实际获胜的 alpha，合计需要 **675 个完整 Linear 候选执行**，相对 scalar10 的 1,680 次减少 **59.82%**。按这组候选子集重选，所有已保存 M2 行赢家都仍在候选集中，所以在这些既有 M2 输入/选择结果上行选择保留率为 100%，搜索损失变化为 0。

这是利用已完成十点搜索结果形成的探索性冻结建议；它没有节省已经付出的搜索成本，也不是新数据验证。没有在缩减网格上提交完整模型运行，因此不能据此宣称模型张量或 PPL 完全相同。

## 直接候选分数与覆盖范围

v18 M2 保留全模型每行的原赢家直接 MSE 和 alpha=1 直接 MSE，但没有保留每行十个 alpha 的完整分数。因此全模型的最优/次优间隔、被移除赢家的精确 3/4/5 子集损失不可恢复。没有用二次型代替这些分数。

v24/v30 可复核到 480 个完整网格直接分数（48 个固定代表行 × 10 alpha），覆盖 12 个目标 Linear-bank、每个仅 4 个输出行。代表行选择分布为 0.8: 18 rows, 0.9: 28 rows, 1.0: 2 rows；best-second gap mean/median/min = 0.000139232253/4.07002528e-05/2.11101745e-07 MSE; strict exclusive winners = 48/48; exact-tie rows = 0。该样本中固定 3 候选子集即可保留全部 48 行选择、search 损失增加为 0，但这只适用于这些代表行。表内复现了原逐行选择和“大 alpha 优先”的精确并列规则；其预算子集结果按原 direct search SSE 精确计算，并在 `SUBSET_RESULTS.csv` 给出逐行、逐模块和全局的最优/次优间隔、独占赢家数、原选择保留率、search 损失增量及最差行。它与正式 v18 M2 使用相同模型版本、FP16、scalar10 网格和行级 direct-MSE 选择语义，但 v24 候选 Hessian/search 输入来自每 bank 16 篇文章，不是 v18 的 128 篇正式校准输入；因此这些代表行结果不替代完整 M2 预算损失。

## 成本与传播边界

候选成本按完整 Linear GPTQ candidate executions 计数。正式 M2 历史基线为 168×10=1,680 次；预算 3/4/5 的全局固定网格投影为 504/672/840 次。预算 3/4/5 的逐模块变长集合计数见 `COST_PROJECTION.csv`。这些是候选次数投影，不是实测时间；原 v18 实测 calibration wall 为 2,115.94 秒，不按候选次数线性换算。

若缩减子集改变任何模块的 alpha 选择，后续输入与 Hessian 可能随前缀变化；v24 缓存上的逐行损失不代表缩减网格的独立整模型运行。即使逐模块赢家并集在现有 M2 行结果上保持所有选择一致，也只说明既有输入下的选择一致性；没有缩减网格的完整提交/传播证据，不宣称模型张量或 PPL 完全相同。

## 执行边界

仅读取已有 search 产物；未读取 P3，未修改 v39 或历史产物；没有 GPU 初始化、模型前向、GPTQ、新 held 评分、PPL 或整模型量化。CPU 分析用时 3.515 秒（上限 300 秒）。历史数据上的候选子集设计是探索性分析，不称为新数据验证。
