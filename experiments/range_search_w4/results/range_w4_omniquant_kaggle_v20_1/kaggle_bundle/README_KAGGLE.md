# v20.1 Kaggle matched-shape preflight

This bundle reuses the v20 OmniQuant Qwen2.5 port at the frozen upstream commit and model revision. It runs only short 2048-token diagnostic updates on layers 0, 12, and 23. It never starts the formal 20-epoch calibration or a PPL evaluation.

## Frozen definition

- Model: `Qwen/Qwen2.5-0.5B-Instruct`, revision `7ae557604adf67be50417f59c2c2f167def9a775`, FP16.
- OmniQuant: `OpenGVLab/OmniQuant`, commit `feffe8ea87d80f7bb57b6e25e7cff9dc950fcc14`.
- Quantization: official asymmetric affine W4A16, group size 128, LWC enabled, LET disabled.
- Calibration: the exact v16/v18 128-sample manifest, 2048 tokens per sample, seed 20261005. The runtime verifies the serialized manifest and every sample token hash before use.
- Device: one GPU, `cuda:0`. Other visible devices are inventoried but unused.
- Formal updates: 24 blocks × 20 epochs × (128 samples / batch 1) = 61,440 optimizer updates. This count is verified from the v20 patched upstream loop; the preflight overrides only an explicit smoke step limit.

## Run in Kaggle

1. Upload `kaggle_bundle_v20_1.zip` as a Kaggle dataset input, or upload the extracted `kaggle_bundle/` folder contents as a dataset.
2. Enable one GPU. Internet is needed only if the exact model revision is not attached as an input.
3. Run `KAGGLE_PREFLIGHT.ipynb`, or use the commands in `KAGGLE_COMMANDS.md`.
4. Copy the generated `/kaggle/working/range_w4_omniquant_kaggle_v20_1/` directory back to the local v20.1 result directory.

The notebook discovers the bundle under `/kaggle/input`; if only the zip is attached, it extracts the bundle to `/kaggle/working`. Runtime outputs also go under `/kaggle/working`. The runner selects only `cuda:0`, even if Kaggle exposes more than one GPU.

## Prefix and cost interpretation

The representative inputs are captured from the frozen real token IDs through the native FP16 full model. L12/L23 therefore use native FP16 prefix activations. Their shapes, sequence length, tokens, and batch size match the formal run, but their distributions are not the eventual sequentially quantized-prefix distributions. The preflight measures layer cost and migration correctness; it does not validate quantized-prefix quality or claim exact formal wall time. That limitation is retained in the report and cost confidence.

The 8-step L0 sequence uses one fresh target block, one optimizer, and one LWC state across all eight updates. The timing runs use a fresh block/optimizer per representative layer and count the first update as warmup. CUDA synchronization is performed around measured intervals.

No runtime report is considered complete unless `KAGGLE_ENVIRONMENT.json`, calibration identity, LWC checks, three layer timings, three memory records, capture timing, cost breakdown, and correctness checks are generated by a Kaggle GPU runtime.
