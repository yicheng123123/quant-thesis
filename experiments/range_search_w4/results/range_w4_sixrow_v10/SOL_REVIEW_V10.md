# v10 独立审查：W4 dynamic GPTQ 的逐行 clipping 偏好

审查日期：2026-09-29。范围仅包括已保存的 v8、v9、v10 代码、冻结协议、FP 输入缓存、候选权重和原始结果。本次没有重新量化模型，也没有启动新实验。以下百分比均以同一行、同一 split 的 native dynamic GPTQ（α=1）为基准；正的 held-out gain 表示输出 SSE 降低。每个 split 两侧各有 4 篇互不重叠的文章、每篇 128 token，因此同一行内 SSE 和 MSE 的相对增益相同。

## 1. Correctness audit

**结论：审查范围内 PASS，没有发现必须停止科学解释的关键错误。** 我独立读取全部 60 份 row-split JSON、600 个候选、对应的候选权重、FP 输入缓存和 v9 manifest；没有仅依据 `correctness_checks.json` 的 PASS 字段。

- v9 `splits_manifest.json` 的 SHA-256 为 `34a24ef8602b8ce1e38e7a284f112acf7f766962d87d737f69148b78bcfaba78`，与 v10 引用值一致。10 个 split 共 80 个不同文章 ID 和 80 个不同 token hash，token ID 逐条重算 hash 相符；search/held-out 在文章和 token 层面均不重叠，且与 v8 的首 8 篇参考文章不重叠。v10 60 份记录中的文章 ID 均与 manifest 对应。
- L23R448 的 10 份记录标注 `source=v9_existing`、本轮候选数 0。逐份核对 v9 源文件 SHA、所选 α、文章 ID、全部 100 个候选的 SSE、MSE、权重误差、scale、zero、权重 hash 和耗时，均与 v9 原始 JSON 相同；不是重新运行的 v10 结果。
- `dynamic_gptq` 每次调用均以 `original_weight.float().clone()` 建立 work state；不同 α 只共享与候选无关的 Hessian 统计量。50 份新记录使用的每行 pristine W hash 跨 split 一致，并与 v8 对应行相符；代码在候选循环前后也核对原始 W hash。没有发现候选间状态污染。
- Hessian 只取 search 文档；候选由 search 输出 MSE 的 `argmin` 选择，held-out SSE 不进入选择。虽然实现会为每个候选计算 held-out SSE 并存档，选择语句只读取 search MSE。全部 60 份记录的 0.1–1.0 网格、α=1 基准、所选 α、search/held-out gain 由原始候选复算一致。
- 60 行 `per_row_split_results.csv` 和 600 行 `alpha_landscapes.csv` 与 raw JSON 的损失、scale、zero 等字段逐项一致；`summary.json` 的逐行均值、中位数和 pooled gain 可由 raw JSON 独立复算。全部 600 份已保存候选权重的 hash 与 raw JSON 一致；用保存的 FP 输入和权重直接重算 1,200 个 search/held-out SSE，最大相对差异为 `9.27e-7`。其中明确抽查了 L0R0、L0R448 和 L23R448。
- α=1 的 v10 L0R0/S00 原生 GPTQ spot parity：FP16 权重、7 组 scale/zero、search/held-out SSE 均完全相等。v8 另有 7 组入口权重、scale/zero 的原生 parity，以及六行在 v8 独立 split 上的 FP16 权重 parity。v10 的其余 59 个 row-split **没有**逐例重新运行原生 GPTQ；因此“全 60 例逐一严格 parity”仍未经检验。当前代码的动态 group 入口和补偿顺序与已通过的 parity 路径相同，足以继续作局部描述性分析。
- v8、v9 当前文件树的 SHA-256、大小、纳秒修改时间均与 v10 preflight 记录的指纹完全一致，证明本轮运行及本次审查未改变这些历史树。该实验目录在当前 Git 状态下未被跟踪，因此无法仅凭 Git 建立 preflight 以前的完整历史来源；这不是此次运行改写历史文件的证据。

## 2. 六行逐 row 结果与稳定性

P/T/R 分别是 held-out 相对增益大于 `1e-4`、绝对值不大于 `1e-4`、小于 `-1e-4` 的 split 数。α 计数是 **search** 选择结果，不是 held-out 调参结果。

| 行 | 所选 α 分布与范围 | P/T/R | held-out 平均 / 中位增益 | 最差 split | 行内 pooled 增益 | 审查分类 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| L0R0 | 0.7×4、0.8×4、0.9×2；0.7–0.9 | 10/0/0 | +28.67% / +28.38% | +19.40% | +29.03% | 稳定 clipping-sensitive |
| L0R448 | 0.8×1、0.9×9；0.8–0.9 | 6/0/4 | −1.20% / +3.95% | **−58.49%** | +0.91% | 不稳定，存在严重泛化失败 |
| L12R0 | 0.8×3、0.9×5、1.0×2；0.8–1.0 | 5/2/3 | +7.95% / +3.61% | −17.99% | +9.05% | 混合 / 不稳定；不能仅称中性 |
| L12R448 | 0.9×8、1.0×2；0.9–1.0 | 4/2/4 | −0.10% / 0.00% | **−43.47%** | +2.68% | 均值接近中性，但有严重尾部风险 |
| L23R0 | 0.6×2、0.7×4、0.8×4；0.6–0.8 | 9/0/1 | +22.52% / +21.57% | −0.14% | +22.62% | 稳定 clipping-sensitive，含一次极小回退 |
| L23R448 | 0.6×4、0.7×4、0.8×2；0.6–0.8 | 10/0/0 | +38.70% / +40.33% | +20.20% | +39.63% | 本协议中最强的稳定 clipping-sensitive 行；来自 v9 |

这些是六个预定代表行在 WikiText-2 train 的 80 篇相邻合格文章上、使用 FP 投影输入得到的局部重建结果。L23R448 曾因 v8 的正结果被单独用于 v9 深入检验；不能将“3/6 稳定”当成全模型 row prevalence 的无偏估计。

## 3. pooled +25.13% 的解释

逐行将十个 split 的 held-out SSE 求和，所有行再相加：D 为 `79.638902`，C 为 `59.627797`，净减少 `20.011105`，故 pooled gain 为 **25.13%**。各行的分母差异很大：

| 行 | D SSE | 净减少 SSE | 占总净减少 |
| --- | ---: | ---: | ---: |
| L0R0 | 0.077409 | 0.022472 | 0.11% |
| L0R448 | 0.197940 | 0.001793 | 0.01% |
| L12R0 | 25.319033 | 2.292050 | 11.45% |
| L12R448 | 7.913396 | 0.212241 | 1.06% |
| L23R0 | 4.690072 | 1.060712 | 5.30% |
| L23R448 | 41.441051 | 16.421838 | **82.06%** |

前两大贡献行 L23R448 与 L12R0 合计占 **93.52%**。去掉 L23R448 后，其余五行 pooled gain 仍为 **9.40%**。因此 +25.13% 主要描述这些不同误差尺度的行的加权总 SSE，不能替代行级一致性：L0R448 与 L12R448 的总体加权收益虽略正，逐 split 平均增益却为负，而且出现大幅回退。

## 4. row-specific clipping preference：有何证据

六行呈现明显的**局部偏好差异**：L0R0、L23R0、L23R448 在十个互不重叠 split 上分别有 10、9、10 次改善；另三行的结果混合或近中性，并有较大的负尾部。固定 α=0.8 在上述三个稳定行分别赢 10、8、10 次，却使 L12R448 输 9 次。该差异支持“某些行具有可迁移的 moderate-clipping 区间，其他行按当前 search 选择规则不具备同样可靠的收益”这一**有限范围内的现象**。

精确 α 并非当前的主要信号。三个稳定行的单一众数均最多只出现 4/10 次，所选 α 却各自集中在 0.6–0.9 的窄带；相反，L0R448 有 9/10 次选 0.9，L12R448 有 8/10 次选 0.9，held-out 仍不稳定。因此**所选 α 一致并不保证泛化，一致改善也不要求完全相同的 α**。现有数据更支持先辨认“哪类行有可靠的 clipping 区间”，随后才考虑精细 α 搜索。

“另一些行完全不应 clipping”尚未得到证明。例如 L12R0 的固定 α=0.8 在 8/10 split 改善、行内 pooled gain +13.91%，优于其 search-selected C 的 +9.05%；这说明当前按小 search 集选 α 的规则也可能失效。任何基于这些 held-out 结果制定的固定 α 或行选择规则，都需要新的独立验证，不能拿同一 10 split 回报为验证收益。

## 5. 失败案例与可用诊断

下表的 top1/top2 margin 定义为 `(search SSE 第二名 − 第一名) / 第二名`。各案例的 held-out 最优 α 仅供**事后诊断**，不得用于重新选择候选。

| 案例 | search 选 α / 第二名 | top1/top2 margin | search gain | held-out gain | held-out 景观 |
| --- | --- | ---: | ---: | ---: | --- |
| L0R448/S09 | 0.9 / 0.8 | 13.83% | +24.10% | **−58.49%** | α=1 最低；0.9 的 held-out SSE 为 D 的 1.585 倍，0.8 为 1.730 倍 |
| L12R448/S07 | 0.9 / 1.0 | 7.34% | +7.34% | **−43.47%** | α=1 最低；0.9 为 D 的 1.435 倍 |
| L12R0/S06 | 0.8 / 0.9 | 5.08% | +10.77% | **−17.99%** | α=1 最低；0.9 仅退化 1.71%，0.8 退化 17.99% |

这三次回退均发生在 search 明确偏好 α<1、held-out 偏好 α=1 时。尤其 L0R448/S09 的 13.83% margin 不能解释为“几乎打平而误选”；L12R448/S07 也不是完全平坦的 search 谷底。有限 search 文章上的排序与 held-out 排序不一致，是原始景观直接支持的描述。

我从已存 FP 输入和 pristine W 读取了基本诊断，没有重新运行模型。三案例的 held-out/search 全局激活 RMS 比分别为 **1.003、0.989、0.984**；逐特征 RMS 相对变化中位数分别为 **3.9%、5.1%、5.2%**，未显示一个共同的异常整体幅度。L0R448、L12R448、L12R0 的 `max(abs W)/RMS(W)` 分别为 **4.27、4.30、3.26**，而 W 对同一行十个 split 不变，不能单独解释某个 split 的失败。缓存的 Hinv 上三案例的逆 Cholesky 因子对角最大/最小比分别约 **9.05、7.95、7.91**；L0/S09 是本层十 split 中最高值，L12 两个值处于本层常见范围。这个比值不是 Hessian 条件数。现有记录没有逐组补偿轨迹、可靠的完整 Hessian 条件诊断或因果干预，**不足以给失败归因**。

## 6. universal α 检验

仅按要求检查已有景观中的固定 α=0.7、0.8、0.9。下列结果是事后描述，不据 held-out 选择新的通用参数。

| 固定 α | 六行×十 split 的 P/T/R | pooled SSE gain | 最差单 split | 重要行级问题 |
| --- | ---: | ---: | ---: | --- |
| 0.7 | 29/0/31 | +0.30% | −146.01% | L0R448、L12R0、L12R448 各 0/10 赢 |
| 0.8 | 42/0/18 | +24.03% | −73.01% | L12R448 仅 1/10 赢；L0R448 最差 −73.01% |
| 0.9 | 43/0/17 | +16.46% | −58.49% | L0R448 4/10 回退；L12R448 5/10 回退 |

对照 search-selected C：44/4/12，pooled +25.13%，最差 −58.49%。α=0.8 的 pooled 总量确实接近 C，但仍有 18 个 held-out 回退，且这个观察来自同一份 held-out 景观。**当前没有一个已检验的固定 α 同时满足跨行稳定、较小尾部风险和强 pooled 收益**；不能因 pooled +24.03% 就称其可替代逐行选择，也不能断言任何未来 universal α 都不存在。

## 7. 当前最可信的科学假设与 feature analysis

最可信的工作假设是：在该模型的 symmetric W4 dynamic G128 GPTQ 与 FP `q_proj` 输入下，*是否具有稳定的 moderate-clipping 收益*存在行间差异；安全的行选择可能比把每行 α 网格再加密更重要。当前 α 搜索目标对部分行的 held-out 排序预测失败。这个表述是研究假设，不是已验证的选择器或误差机制。

现有六行足以生成机制假设、列出权重尾部、激活分布、Hinv/补偿以及景观 margin 等候选特征；**不足以训练 classifier/predictor，也不足以宣称某个特征区分稳定行**。基本 max/RMS 与全局激活 RMS 检查没有给出统一解释。下一轮应把这些特征作为预先定义的描述性字段，随后在更多随机固定行上检验关联；不能在这六行上反复挑特征并报告预测准确率。

## 8. 当前不能声称什么

- 不能以 25.13% pooled gain 声称典型行收益、全模型收益或 PPL 改善；L23R448 单行贡献 82.06%。
- 不能把三个稳定行的比例 3/6 推广为全模型 prevalence；行和投影的抽样范围过窄，v9 又对一个正向行做过专门跟踪。
- 不能称精确 α 可跨 split 复现；稳定行的单一 α 众数仅 4/10。也不能称接近 1 的行永远不该 clipping，L12R0 是反例。
- 不能把粗略权重/激活/Hinv 描述当成失败的因果机制；不能从六行训练安全 row selector。
- 不能推断量化前缀输入、其他投影、全部层、整模型 PPL、下游任务或在线推理加速。

## 9–10. 下一步唯一推荐实验与 96-row 决定

**96-row prevalence：GO，但只推荐分阶段、事先冻结 gate 的版本；本次审查不执行。** 目的应是估计 clipping-sensitive 行在固定层/投影中的出现率、投影与层差异、α 区间和回退频率，而非证明 PPL。现有三个稳定行给出继续研究的理由，三个不稳定行表明必须在更大、与收益无关的行样本上估计风险。单独延长六行 feature analysis 不能回答 prevalence；直接给所有行做 full-grid ×10 split 也没有必要。

建议的预注册轮廓：

1. 在查看新行结果前，按固定 seed 于 layer 0/12/23 的 `q_proj`、`o_proj`、`up_proj`、`down_proj` 各抽 8 个有效输出行，共 96 行；按投影分层报告，不把六个既有代表行自动当作随机样本。若固定抽样碰巧包含已完成的 q_proj 行，则从 v9/v10 导入相同 split 的原始结果。
2. 先在每种投影做 α=1 原生 parity 和显存/时间可行性检查，再冻结运行预算。`down_proj` 的输入宽度是 4864，q/o/up 的输入宽度为 896；其 Hessian 元素数约为后者的 29.5 倍。因此 v10 的每候选约 0.252 秒不能直接外推为 96 行总成本。若原生 parity、内存或预定预算 gate 失败，停止并保留结果，不临时删去最贵投影。
3. Stage 1：所有 96 行使用 v9 冻结的 S00–S02、原生动态 GPTQ、同一 0.1–1.0 十点共享 α 网格；每个 split 只用 search MSE 选 α，held-out 只作评价。最多 2,880 个候选点（可复用的既有点除外）。v10 q_proj 速率下的约 12 分钟仅是 **同宽度参考量**，不是包含 `down_proj` 和数据捕获的预算承诺。
4. 建议**在运行前**冻结如下 Stage 2 gate：Stage 1 中至少 2/3 split 改善超过 2%、中位改善超过 5%、最差不低于 −10% 的行为“待确认正向”；0/3 正向且所有回退均不超过 10% 的行为“清晰负向”；其余行为“混合/风险”。所有“待确认正向”和“混合/风险”行进入 S03–S09；“清晰负向”行按行标识与 seed 42 的固定 hash 顺序抽取 `ceil(25% × 该组行数)` 个，作为负向审计样本。最终“稳定正向”的预设判据为 10 split 至少 8 次正向、中位改善超过 5%、最差不低于 −10%，且至少 8 次所选 α 落在某个连续的三个网格点内。最终分开报告全 96 行的 Stage 1 描述结果和 Stage 2 的条件确认结果，不把条件子集的正向率冒充总体 prevalence；如需总体稳定 prevalence，必须按预设抽样概率加权并给出不确定区间。这些门槛只是下一轮的预注册建议，本次审查没有执行或声称已经冻结。

在新增行上同步记录事先列明的权重、激活、Hinv/GPTQ 和景观特征用于**探索性**机制分析；预测规则需要独立行或独立数据再验证。全面的 96×10 split×10 α 共 9,600 个候选点，按 q_proj 速率约 40 分钟仅为同宽度候选计算参考量；更宽的 `down_proj` 与 Hessian 构建可能显著提高成本，当前不建议一次性启动。

## 11. Full-model PPL 决定

**NO-GO。** 目前仅验证六个 `q_proj` 行、FP 投影输入；不知道其他投影和行的稳定正向比例，已有 −58.49% 与 −43.47% 的局部回退，也没有由独立数据验证的安全 row-selection 规则。PPL 前至少需要：跨投影/层的 prevalence 与尾部风险估计、候选规则在未参与制定的行/文档上的验证、全层动态 GPTQ 接入和 quantized-prefix 输入下的正确性与成本检查。只有这些前置证据通过后，才能在原有标准整模型协议上评估 PPL。
