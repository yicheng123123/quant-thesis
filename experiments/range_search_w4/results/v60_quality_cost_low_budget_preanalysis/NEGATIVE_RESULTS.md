# v60 负结果与未覆盖证据

1. 没有中间 raw-X 直接输出误差。保存的 moves 足以精确恢复固定 C 二次型的接受状态及累计候选数，但不能将中间公式轨迹冒充逐步 raw-X 重算。
2. 没有低预算完整模型的实际运行时间、传播验证、checkpoint、held 或 PPL。8/16 更新结果只是从原 32 次运行、各模块原 X/C 中截取的局部 search 轨迹。
3. 32 次上限行仍占多数：v55 为 281,097/304,128；v56 为 273,002/304,128。后半段第17–32次接受仍贡献约27%的完整局部 C 二次型下降。
4. 预算8把候选数降至原运行约25%，但基于 v56 同步计时的条件模型只估算节省完整 block timer 的3.02%。此值不是实测，不能由候选减少比例换算。
5. C构建和全矩阵终态检查在降低接受预算后仍必须执行。selection无法从候选评分计时中分拆；代码更新和p更新也没有独立timer。纯GPU kernel时间、各恢复子阶段的CPU/GPU拆分不可识别。
6. v45/v46/v49校准传播继续为UNKNOWN。v18 M1/M2的记录运行时支持tuple接口，但缺少逐调用类型和穷尽前缀核验；v59统一评测不补充该历史校准证据。
7. v55/v56完整有效运行的接受拒绝数、候选评价预算触顶数、更新上限行数按原日志报告；这些通过项不提供低预算整模型质量保证。

因此，现有结果不足以把低预算修复作为“质量保持且更快”的主张，也不足以选择一个预算开展GPU完整运行。本轮收束，不继续追加局部GPU实验。
